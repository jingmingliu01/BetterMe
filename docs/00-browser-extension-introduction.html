浏览器插件开发速览

预计阅读时间：45-60 分钟。本文按你已有的 Web/iOS 背景来解释 Chrome Extension 开发。

一句话模型：浏览器插件是一个运行在浏览器权限模型里的小型 Web App。它有自己的页面、后台 service worker、浏览器 API、存储空间和商店审核规则。

1. 插件和普通 Web App 的区别

维度普通 Web AppChrome Extension
入口用户访问你的域名用户安装扩展，Chrome 加载 manifest.json
前端 UI网页、SPA、SSRpopup、options page、extension page、side panel、content overlay
后台逻辑你的 server 或 serverless functionextension background service worker，在用户浏览器里运行
权限浏览器 Web APIWeb API + Chrome Extension API，需要 manifest 声明权限
发布部署到自己的 hosting打包上传 Chrome Web Store，被政策审核
代码可见性前端可见，后端不可见插件包里的代码都在用户机器上，可被解包查看

官方入门文档：Chrome Extensions Get Started

2. 插件由哪些部分组成

manifest.json

插件的配置文件，类似 iOS 的 Info.plist + Web App 的 package metadata。它声明名称、版本、权限、入口文件、background service worker、web accessible resources 等。

Background Service Worker

插件后台。没有 DOM，适合处理事件、读写 storage、管理 DNR rules、请求 LLM provider。BetterMe 的“extension backend”就是它。

Extension Pages

插件自己的网页，例如 onboarding、block page、settings page、AI Check page。可以用 React + TypeScript 构建。

Content Scripts

注入到网页上下文里的脚本。BetterMe MVP 尽量少用，因为我们不读页面内容，主方案是 DNR redirect。

DeclarativeNetRequest

声明式网络规则。可以 block/redirect 请求，不需要查看请求内容，适合 privacy-first blocker。

Storage / IndexedDB

保存 blocked sites、settings、track summaries、encrypted API key 等本地数据。

3. “Extension Backend” 到底是什么

BetterMe MVP 没有你自己的云后端。这里的后台指的是 background service worker，它运行在用户浏览器里。

React block page / settings page
  -> chrome.runtime.sendMessage(...)
  -> background service worker
  -> chrome.storage / IndexedDB
  -> fetch("https://api.openai.com/v1/chat/completions")

它和你自己的后端区别很大：

问题Background Service Worker你自己的 Backend
运行位置用户浏览器你的服务器
能否保密代码不能可以
能否保密 prompt不能可以
能否安全保存平台密钥不能保存你的共享密钥可以
适合做什么本地规则、用户 BYOK、隐私优先逻辑账务、订阅、license、hosted AI、审计

官方文档：Extension Service Workers

4. BetterMe 为什么 MVP 用 DNR Redirect

BetterMe 有两个可能的阻断方案：

方案优点缺点
Blur Overlay视觉上像在原网页上弹窗网页先加载，可能短暂暴露内容；需要 content script；不同网站稳定性差
DNR Redirect稳定、隐私好、不读页面内容、审核解释清楚不是原网页模糊背景，而是跳到 extension block page

MVP 选择 DNR redirect：访问 blocked target 时，主 frame 被重定向到 BetterMe 的 block page。

官方文档：chrome.declarativeNetRequest

数据建议位置说明

官方文档：chrome.storage

6. Privacy 是插件开发的核心问题

Chrome Web Store 对用户数据非常敏感。BetterMe 的隐私叙事应该保持简单：

  • 不读取完整 browser history。
  • 不读取页面内容。
  • 默认只保存用户手动添加的 domain 或 exact URL。
  • AI Check 由用户主动启动。
  • 发送给 LLM provider 的上下文只包含必要信息：target、strictness、recent summary、pattern memory、current conversation。
  • 用户 API key 本地加密保存，BetterMe 不接触。
  • 提供本地数据导出和删除。

政策文档：Chrome Web Store User Data FAQ

7. 哪些行为容易触发商店 Policy 风险

NSFW preset 尤其要谨慎。Chrome Web Store 不允许包含色情裸露、显式性内容，或导流到商业色情网站。BetterMe 可以提供 NSFW blocking preset，但 MVP 不展示具体 URL，不写任何导流文案。
风险行为BetterMe 注意事项
权限过大不要默认申请 <all_urls>，优先使用 DNR 和用户添加的目标。
读取页面内容MVP 不做；如果未来做 overlay，也不要采集正文。
展示成人网站列表NSFW preset 默认隐藏具体 URL，只展示分类名和说明。
远程加载代码插件逻辑必须打包进 extension，不要运行远程下载的 JS。
误导用户不要宣称“无法绕过”；用户可以禁用或卸载插件。
API key 处理不透明明确说明 key 存本机、加密保存、直接发给用户选择的 LLM provider。

政策链接：Mature & Sexually Explicit Material，Chrome Web Store Program Policies，Manifest V3 Requirements

9. 你应该能怎么向别人解释插件开发

你可以这样说：

Chrome Extension 是一个被浏览器安装和托管的小型 Web 应用。它有 manifest 声明权限，有 React 页面做 UI，有 background service worker 做本地后台逻辑，有 content script 可选地注入网页。它可以通过 Chrome Extension API 修改浏览体验，比如拦截或重定向请求、保存本地设置、和浏览器标签通信。和普通 Web App 最大区别是：代码跑在用户浏览器里，权限需要商店审核，隐私和最小权限是核心设计约束。
